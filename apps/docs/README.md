# Documentation site

The TanStack Start documentation site. It reads the shared Markdown, UI tokens, showcase variants, and registries. It uses the React UI components directly.

From the workspace root:

```sh
bun run docs -- --host 127.0.0.1
```

Development runs at http://127.0.0.1:3001. Vite+ provides development, production builds, previews, and repository checks. TanStack Start and the React plugin follow the [official Vite setup](https://tanstack.com/start/latest/docs/framework/react/build-from-scratch).

## Validate production builds

```sh
bun run docs:build
bun run docs:preview -- --host 127.0.0.1
```

`vite.config.ts` includes Alchemy's Cloudflare Vite plugin, so development, builds, and previews all run the Worker in workerd. The preview serves the built Worker and assets at http://127.0.0.1:3002 with the production asset settings.

Use the browser's performance and Lighthouse tools on the production origin with identical mobile throttling and cache settings to assess loading and interaction behaviour. Repeat cold loads and client navigation separately; initial loading and navigation have different costs.

## Implementation

- `packages/content` supplies the Markdown and navigation taxonomy. A Vite plugin reads frontmatter into a small navigation module; Markdown compilation runs once in isolated Node tooling. A small virtual index exposes one lazy module per document; `/` and `/docs/$` load only the requested module during SSR or client navigation. TanStack Router preloads on intent and caches immutable page data for the session. No document RPC or browser Markdown parser is needed.
- `packages/ui` supplies the shell primitives, Command search, Sheet mobile navigation, tabs, controls, code blocks, copy buttons, icon sprite, and all style tokens.
- Scrolling follows the shared UI defaults: document, code, table, and textarea scrollbars use the native thin style; sidebar and popup scrollers use `ScrollArea` with the same colors and sizing tokens. Document scrolling stays native for anchors and router scroll restoration. Markdown tables use the shared Table primitives and a keyboard-accessible scrolling container.
- `packages/showcase` supplies the same live examples and playground metadata. Examples and playground controls load as they approach the viewport through an `import.meta.glob` over the showcase variants. Source tabs fetch source code when opened. Headings and descriptions remain server-rendered.
- TanStack Start prerenders every catalogued document inside workerd. Vite serves generated HTML and assets; the Start handler handles requests without a matching asset, including missing pages. `robots.txt`, `sitemap.xml`, and `sitemap-index.xml` are dedicated server routes. Start uses its default configuration. Build scripts verify that generated HTML references assets present in the same output directory.
- The layout uses a sidebar and inset content panel, with the same 959px mobile breakpoint. Mobile navigation uses a native Sheet with focus management and scroll locking. Search uses the native Command component and supports Mod+K.
- Canonical URLs are `https://ui.erbium.app`. Metadata, JSON-LD, sitemaps, Markdown pages, JSON documentation, `llms.txt`, OpenAPI, agent skills, social cards, fonts, and registry URLs are included.

Vite+'s Bun workspace can resolve multiple instances of its Vite runtime through peer dependencies. The isolated content tooling server uses Vite+'s runnable environment factory so runtime identity checks work in this workspace. Application aliases come from `tsconfig.json` through Vite's `resolve.tsconfigPaths`; the isolated content tooling server uses the same setting.

`.cache/theme.css` and `src/routeTree.gen.ts` are generated by the configured plugins. Do not edit generated files manually. These plugins do not modify shared UI source or generated registries.

## Deployment

Alchemy owns deployment (`packages/infra/alchemy.run.ts`). The separate preview stage uses the `default` profile:

```sh
bun run deploy:preview:plan
bun run deploy:preview
```

Deployment prints the workers.dev URL alongside the production origin. Preview pages retain production canonical URLs and disable indexing. Alchemy supplies the public Web Analytics token; Worker invocation logs and traces capture requests that fall through static asset serving. Production (`ui.erbium.app`) deploys from the `prod` stage. See [infrastructure setup](../../packages/infra/README.md).

Alchemy injects its own Cloudflare plugin into deploy builds and sets `ALCHEMY_CLOUDFLARE_VITE_INJECTED`. The config-file plugin stands down for those builds, except in the preview server that Start reopens from `vite.config.ts` to prerender pages.

## Build and content boundaries

`static-content-plugin.ts` owns Node-only compilation and artifact generation. Markdown is parsed into TanStack Markdown trees with stable heading IDs. Browser page modules contain trees, headings, and showcase metadata; raw Markdown and example source remain separate downloadable artifacts. The React renderer maps Markdown elements to shared UI components without reparsing the source.

Run `bun apps/docs/verify-build.ts` from the workspace root to check an existing build. This check catches stale prerender output referencing assets from a different build.
