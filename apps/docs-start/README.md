# Documentation site

The TanStack Start documentation site. It reads the shared Markdown, UI tokens, showcase variants, and registries. It uses the React UI components directly.

From the workspace root:

```sh
bun run docs:start -- --host 127.0.0.1
```

Development runs at http://127.0.0.1:3001. Vite+ provides development, production builds, previews, and repository checks. TanStack Start and the React plugin follow the [official Vite setup](https://tanstack.com/start/latest/docs/framework/react/build-from-scratch).

## Validate production builds

```sh
bun run docs:start:build
```

In another terminal:

```sh
bun run docs:start:preview -- --host 127.0.0.1
```

The Start site is available at http://127.0.0.1:3002.

Use the browser's performance and Lighthouse tools on the production origin with identical mobile throttling and cache settings to assess loading and interaction behaviour. Repeat cold loads and client navigation separately; initial loading and navigation have different costs.

## Implementation

- `packages/content` supplies the Markdown and navigation taxonomy. A Vite plugin reads frontmatter into a small navigation module; Markdown compilation runs in isolated Node tooling and supplies generated page data to the server.
- `packages/ui` supplies the shell primitives, Command search, Sheet mobile navigation, tabs, controls, code blocks, copy buttons, icon sprite, and all style tokens.
- Scrolling follows the shared UI defaults: document, code, table, and textarea scrollbars use the native thin style; sidebar and popup scrollers use `ScrollArea` with the same colors and sizing tokens. Document scrolling stays native for anchors and router scroll restoration. Markdown tables use the shared Table primitives and a keyboard-accessible scrolling container.
- `packages/showcase` supplies the same live examples and playground metadata. Examples load as they approach the viewport. Source tabs fetch source code when opened.
- Local Node builds prerender documentation pages. Cloudflare builds render documentation HTML in the Worker. The production preview serves their generated HTML before the Start request handler. The handler provides server functions, agent resources, redirects, and 404 responses.
- The layout uses a sidebar and inset content panel, with the same 959px mobile breakpoint. Mobile navigation uses a native Sheet with focus management and scroll locking. Search uses the native Command component and supports Mod+K.
- Canonical URLs remain `https://ui.erbium.app` for comparison. Metadata, JSON-LD, sitemaps, Markdown pages, JSON documentation, `llms.txt`, OpenAPI, agent skills, social cards, fonts, and registry URLs are included.

Vite+'s Bun workspace can resolve multiple instances of its Vite runtime through peer dependencies. The SSR environment is explicitly created with the application's runnable environment factory and Start's development middleware is explicitly enabled, so its runtime identity checks work in this workspace. The preview dependency plugin prebundles dependencies from their owning UI/showcase workspaces, including CommonJS dependencies reached through lazy imports.

`.cache/theme.css` and `src/routeTree.gen.ts` are generated by the configured plugins. Do not edit generated files manually. These plugins do not modify shared UI source or generated registries.

## Cloudflare preview

Run `bun run docs:start:cloudflare:build` and `bun run docs:start:cloudflare:preview` to validate the Worker locally at http://127.0.0.1:3003.

The separate Alchemy preview stage uses the `default` profile:

```sh
bun run deploy:preview:plan
bun run deploy:preview
```

Deployment prints the workers.dev URL alongside the production origin. Preview pages retain production canonical URLs and disable indexing. Alchemy supplies the public Web Analytics token; Worker invocation logs and traces capture server rendering. Production (`ui.erbium.app`) deploys this Start site from the `prod` stage. Deployment requires a refreshed Cloudflare profile with Workers Scripts write and Account Settings write permissions. See [infrastructure setup](../../packages/infra/README.md).
